> Интерактивная аналитическая платформа на базе **Power BI** и **Яндекс DataLens**, интегрированная с локальной базой данных **MongoDB**. ## 🎯 Обзор проекта
Этот проект трансформирует сырые выгрузки из базы данных образовательного центра в стратегический аналитический инструмент. Он успешно решает три ключевые задачи:

1. **🗄️ Data Engineering (ETL в СУБД):** Реляционное объединение коллекций (`lessons`, `attendances`, `groups`) на уровне базы данных MongoDB с помощью агрегированных представлений (Views) и жесткая фильтрация целевого онлайн-филиала.
2. **📈 Time-Series Pipeline:** Автоматизированный скрипт очистки данных, который отсекает неполные граничные периоды, устраняет локальные просадки с помощью скользящего среднего (пороговый фильтр 1.5 стандартных отклонений) и применяет медианный fallback-алгоритм.
3. **🤖 Predictive Modeling:** Модель временных рядов на базе линейной регрессии (`scikit-learn`), которая учитывает глобальный тренд развития школы и компоненты календарной сезонности, выстраивая непрерывный прогноз на 6 месяцев вперед.

## 📊 Анализ baseline-модели и технический бэклог

### 1. Выводы по текущей метрике и результатам EDA
В рамках разведочного анализа данных (EDA) были детально изучены паттерны посещаемости EdTech-платформы и выделены два ключевых компонента цикличной активности пользователей:
* **Микро-сезонность:** Выраженная внутринедельная флуктуация трафика с явными спадами посещаемости в выходные дни и пиками в середине недели.
* **Макро-сезонность:** Долгосрочные циклы учебного года, завязанные на календарные периоды спада (летние каникулы, январские и майские праздники) и осенние/весенние пики образовательной активности.

Разработанная baseline-модель на базе линейной регрессии (Linear Regression) зафиксировала качество предсказаний на уровне **R² = 0.11 на 6-месячном горизонте прогнозирования**. 
* **Причина низкого значения метрики:** Обычные временные признаки (one-hot кодирование дней недели и месяцев) не способны в полной мере улавливать авторегрессионную природу временного ряда, нелинейные долгосрочные тренды и резкие календарные аномалии, характерные для сферы EdTech.
* **Роль текущей модели:** Модель успешно выполняет функцию отправной точки (baseline) и архитектурного каркаса для сквозного ML-пайплайна — от извлечения данных из MongoDB до выгрузки финальных предсказаний.

### 🎯 Технический бэклог перехода на последовательные архитектуры

Для повышения точности прогнозирования сформирован пошаговый план миграции на специализированные алгоритмы анализа временных рядов (Prophet / ARIMA):

#### 🛠 Спринт 1: Интеграция статистической авторегрессии (SARIMAX)
* **Проверка ряда на стационарность** — проведение теста Дики-Фуллера (ADF-тест) и построение графиков ACF / PACF для обоснованного подбора лагов авторегрессии (p, q).
* **Реализация модели SARIMAX** — внедрение алгоритма с явным указанием недельного сезонного шага (s=7) для стабилизации учета микро-сезонности.
* **Оценка влияния макро-факторов** — добавление внешних экзогенных переменных (флаги сессий, каникулярных периодов) для сглаживания прогноза.

#### 🚀 Спринт 2: Переезд на Facebook Prophet (Управление календарем событий)
* **Разработка дата-адаптера** — создание прослойки трансформации агрегированных данных из MongoDB в целевой формат Prophet (`ds`, `y`).
* **Моделирование праздников и спадов** — интеграция кастомного календаря праздничных дней РФ и специфических EdTech-событий (летнее затишье) для предотвращения ложных просадок тренда.
* **Тюнинг параметров и декомпозиция** — тонкая настройка точек изменения тренда (`changepoints`) и визуализация извлеченных компонентов через `model.plot_components()`.

#### 📈 Спринт 3: Кросс-валидация и бенчмаркинг
* **Валидация на скользящем окне** — внедрение схемы `TimeSeriesSplit` (или встроенных инструментов валидации Prophet) для корректной оценки качества на 6 месяцев вперед без заглядывания в будущее.
* **Формирование сводного Benchmark** — сведение метрик (R², MAE, RMSE) линейной регрессии, SARIMAX и Prophet в единую аналитическую таблицу для выбора финального production-решения.
* **Обновление выгрузки** — адаптация скрипта экспорта итогового файла `predictions_output.csv` под обновленную структуру данных для дашбордов в Power BI / Yandex DataLens.

## 🚀 Инструкция по локальному развертыванию

### 1. Подготовка репозитория и окружения
Клонируйте репозиторий в локальную папку и установите необходимые библиотеки Python (убедитесь, что на вашем компьютере установлен Python и запущен локальный сервер MongoDB Community Server):

```powershell
git clone https://github.com
cd EdTech-analitics-ml
pip install -r requirements.txt
```

### 2. Развертывание базы данных MongoDB
Для автоматического создания структуры базы данных и наполнения её коллекциями выполните скрипт первичного импорта в вашем системном терминале (PowerShell/CMD):

```powershell
python scripts/db_import.py
```

Далее разверните скрипт агрегированного представления для связывания и фильтрации коллекций. Это можно сделать одним из двух способов:

* **Вариант А (Через системный терминал):** Выполните следующую команду напрямую из корневой папки проекта:
  ```powershell
  mongosh mongodb://localhost:27017/EdTechDB scripts/create_view.js
  ```

* **Вариант Б (Через интерфейс MongoDB Compass):** Откройте MongoDB Compass, подключитесь к вашему серверу, нажмите на вкладку **>_ MONGOSH** в самом низу окна и запустите JavaScript-код агрегации из файла `scripts/create_view.js` напрямую.

*Результат:* В вашей СУБД внутри базы данных `EdTechDB` появится готовое виртуальное представление `bd_online_aggregated`.

### 3. Фоновый запуск ML-пайплайна
Вы можете запустить автономный скрипт прогнозирования для расчета метрик и выгрузки результатов предсказания в плоский файл без открытия графических интерфейсов BI:

```powershell
python scripts/pipeline.py
```
Файл с очищенными историческими данными и прогнозом на 6 месяцев автоматически сохранится по пути `data/predictions_output.csv`.

### 4. Запуск аналитического дашборда Power BI
1. Установите и откройте **Power BI Desktop**.
2. Откройте файл отчета `reports/dashboard.pbix`.
3. Нажмите кнопку **Обновить (Refresh)** на главной панели инструментов. 

Power BI автоматически подключится к вашей локальной MongoDB через встроенный Python-коннектор, пересчитает модель линейной регрессии и обновит все интерактивные графики, KPI-карточки («Всего посещений», «Медиана за историю», «Среднее за историю») и линии тренда на холсте.
